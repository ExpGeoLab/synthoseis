# Fix for `bruges` Import Error (`pkg_resources`)

## Problem
When importing the `bruges` library, the following error occurs:
```text
ModuleNotFoundError: No module named 'pkg_resources'
```
This happens because newer Python environments (especially Python 3.12+) or minimal virtual environments do not include `setuptools` by default, and `pkg_resources` is deprecated. The `bruges` library relies on this module to determine its version number during initialization.

## Solution
Manually patch the `bruges` initialization file to use the modern `importlib.metadata` module instead of `pkg_resources`.

### Steps
1.  **Locate the file** in your virtual environment:
    ```text
    .venv/Lib/site-packages/bruges/__init__.py
    ```
    *(Note: On Windows, this might look like `.venv\Lib\site-packages\bruges\__init__.py`)*

2.  **Open the file** in a text editor.

3.  **Find the import block** near the top (around lines 20-30) that looks like this:
    ```python
    from pkg_resources import get_distribution, DistributionNotFound

    try:
        VERSION = get_distribution(__name__).version
    except DistributionNotFound:
        # ...
    ```

4.  **Replace it** with the following compatible code:
    ```python
    try:
        from importlib.metadata import version, PackageNotFoundError
    except ImportError:
        from importlib_metadata import version, PackageNotFoundError

    try:
        VERSION = version(__name__)
    except PackageNotFoundError:
        try:
            from ._version import version as VERSION
        except ImportError:
            raise ImportError(
                "Failed to find (autogenerated) _version.py. "
                "This might be because you are installing from GitHub's tarballs, "
                "use the PyPI ones."
            )
    ```

5.  **Save the file** and restart your Python kernel/application.

## Important Note
This is a **local patch**. If you recreate your virtual environment or reinstall `bruges`, you will need to apply this fix again. For a permanent team solution, consider adding a post-install script or requiring a specific version of `setuptools` in your `requirements.txt` (though the patch is more robust for Python 3.12+).
